1. โซนเส้นทางหน้าเว็บ (Routes & Pages: src/app/)
ใน Next.js App Router โฟลเดอร์จะทำหน้าที่เป็น URL และไฟล์ที่ชื่อ page.tsx จะทำหน้าที่เป็นตัวเรนเดอร์หน้าจอหลักของ URL นั้นๆ

-src/app/layout.tsx (Root Layout)
 --หน้าที่: โครงสร้างหลักที่ครอบทุกหน้าจอในเว็บไซต์ ใช้สำหรับกำหนด Font, ตั้งค่าธีม และเรียกใช้งานแถบเมนูหลัก (Navbar และ Sidebar) เพื่อให้แสดงผลค้างไว้ในทุกๆ หน้าโดยไม่ต้องเขียนซ้ำ

-src/app/page.tsx (Main Dashboard)
 --หน้าที่: หน้าแรกสุดหลังจากผู้ใช้เข้าสู่ระบบ ทำหน้าที่เป็น Dashboard หลัก ที่ดึงข้อมูลจาก Cloud Firestore มาแสดงผลเป็นตารางรวม Log ปัญหาทั้งหมด (เช่น ปัญหา BMS, ปัญหา Shunt) พร้อมมีแถบค้นหา (Search) และตัวคัดกรอง (Filter) ตามระดับความรุนแรงและฝ่ายเทคนิค

-src/app/login/page.tsx (Authentication Page)
 --หน้าที่: หน้าจอสำหรับให้สมาชิกในทีมกรอก Username (Email) และ Password เพื่อยืนยันตัวตนผ่าน Firebase Authentication ก่อนเข้าใช้งานระบบ

-src/app/reports/create/page.tsx (Log Creation Form)
 --หน้าที่: หน้าฟอร์มสำหรับให้สมาชิกกดเพิ่มรายงานปัญหาใหม่ (ADD+) มีช่องให้กรอกหัวข้อปัญหา (Problem), รายละเอียด (Detail), เลือกประเภท (Type Report), เลือกสิทธิ์ระดับความรุนแรง (Severity Level) และช่องสำหรับแปะลิงก์ Google Drive (Other File)

-src/app/reports/[id]/page.tsx (Dynamic Log Detail & Edit)
 --หน้าที่: หน้าแสดงรายละเอียดเชิงลึกของ Log นั้นๆ (เช่น สมาชิกกดเข้ามาดูจากปุ่ม "View More / More Detail" ในตาราง) รองรับการอัปเดตสถานะงานซ่อม (Done) บันทึกวิธีแก้ไข หรือให้เจ้าของ Log/แอดมิน กดแก้ไขและลบข้อมูลรายงานได้  (หมายเหตุ: เครื่องหมาย [id] หมายถึงเปลี่ยน URL ไปตามรหัส ID ของรายงานฉบับนั้นๆ อัตโนมัติ)

-src/app/admin/page.tsx (Admin Control Center)
 --หน้าที่: หน้าแรกสำหรับผู้ใช้ที่มีสิทธิ์เป็นแอดมิน (หัวหน้าทีม/หัวหน้าฝ่าย)  แสดงภาพรวมระบบและเมนูควบคุมเพื่อเข้าไปจัดการฐานข้อมูลพื้นฐาน

-src/app/admin/departments/page.tsx (Department Management)
 --หน้าที่: หน้าจอสำหรับแอดมินในการเพิ่ม ลบ หรือแก้ไขรายชื่อฝ่ายเทคนิคในทีม (เช่น High Voltage, Low Voltage, Control และฝ่ายอื่นๆ ในอนาคต)

-src/app/admin/report-types/page.tsx (Category Management)
 --หน้าที่: หน้าจอสำหรับแอดมินในการจัดการหมวดหมู่ประเภทของปัญหา (เช่น จัดการเพิ่มตัวเลือกประเภท Battery, Component) เพื่อให้สมาชิกนำไปเลือกในฟอร์มสร้างรายงาน

2. โซนชิ้นส่วนหน้าจอที่ใช้ซ้ำ (Shared Components: src/components/)
เป็นโฟลเดอร์สำหรับเก็บชิ้นส่วนหน้าจอ (UI Components) ที่ถูกเรียกใช้งานในหลายๆ หน้า เพื่อช่วยประหยัดเวลาในการเขียนโค้ดและควบคุมดีไซน์ให้เหมือนกันทั้งเว็บ

-src/components/Navbar.tsx 
 --แถบเมนูด้านบนสุด แสดงโลโก้ของทีม หัวข้อระบบ และชื่อผู้ที่กำลังล็อกอินใช้งานอยู่ปัจจุบัน

-src/components/Sidebar.tsx
 -- แถบเมนูด้านข้างตัวแอปพลิเคชัน ทำหน้าที่เช็กสิทธิ์ผู้ใช้ หากผู้ใช้เป็นแอดมิน จะเปิดเมนูพาร์ท /admin/ ให้เห็น หากเป็นสมาชิกทั่วไปเมนูแอดมินจะถูกซ่อนไว้

-src/components/ReportTable.tsx
 --ชิ้นส่วนตารางที่ใช้แสดงประวัติ Log ปัญหา ออกแบบมาพร้อมช่องค้นหาข้อความ และปุ่มกด Filter คัดกรองข้อมูล

-src/components/ProtectedRoute.tsx
 --ส่วนป้องกันความปลอดภัย (Route Guard) ทำหน้าที่ตรวจสอบว่าผู้ใช้ได้ล็อกอินหรือยัง หากยังไม่ได้ล็อกอินและพยายามจะเข้าหน้า Dashboard ระบบจะบล็อกและเด้งกลับไปหน้าล็อกอินโดยอัตโนมัติ

-src/components/ui/ (Atomic UI ชิ้นเล็ก)
 --Button.tsx: ปุ่มกดส่วนกลางของแอป (กำหนดสี สไตล์ และ Effect ตอนกดให้เหมือนกันทั้งเว็บ)
 --Input.tsx: ช่องกรอกข้อความสำหรับแบบฟอร์มต่างๆ
 --SeverityBadge.tsx: ป้ายกำกับสีเพื่อเตือนระดับความรุนแรงของปัญหา (เช่น สีแดงสำหรับ Critical, สีส้มสำหรับ High, สีเหลืองสำหรับ Medium, สีเขียวสำหรับ Low)

3. โซนประมวลผลหลังบ้าน (Logic & Configurations: src/)
ส่วนเก็บการตั้งค่าเชื่อมต่อเซิร์ฟเวอร์, การเชื่อมโยงฐานข้อมูล และโมเดลชนิดข้อมูลของระบบ

-src/config/firebase.ts (Firebase Connection)
 --หน้าที่: ไฟล์เปิดประตูเชื่อมต่อไปยังบริการของ Firebase SDK โดยดึงค่าความปลอดภัยมาจากระบบ และสั่งเปิดการทำงานของระบบล็อกอิน (Firebase Auth) และฐานข้อมูล NoSQL (Cloud Firestore)  เพื่อนำไปใช้เรียกสั่งการทั่วทั้งแอป

-src/hooks/useAuth.ts (Authentication Logic)
 --หน้าที่: Custom Hook รวบรวมฟังก์ชันการทำงานเกี่ยวกับผู้ใช้ เช่น ฟังก์ชันล็อกอิน ฟังก์ชันล็อกเอาต์ออกระบบ และทำหน้าที่คอยเฝ้าดู (Listen) ว่าปัจจุบันคนที่เปิดเว็บอยู่คือใครและมีสิทธิ์แอดมินหรือไม่

-src/hooks/useReports.ts (Firestore CRUD Operations)
 --หน้าที่: Custom Hook รวบรวมคำสั่งติดต่อฐานข้อมูล Firestore ในการจัดการ Log ปัญหา ประกอบด้วยฟังก์ชัน ดึงข้อมูลรายงานทั้งหมด (Read), สร้างรายงานใหม่ (Create), แก้ไขสถานะปัญหา (Update) และคำสั่งลบรายงานออกจากระบบ (Delete)

-src/types/index.ts (TypeScript Interfaces)
 --หน้าที่: ไฟล์สเปกข้อกำหนดทางเทคนิค (Type Definition) เก็บนิยามโครงสร้างข้อมูล เพื่อให้ระบบรู้ว่า ข้อมูล Report 1 ชุด จะต้องมีฟิลด์อะไรบ้าง (เช่น title, detail, severity, createdBy) เพื่อป้องกันทีมเขียนโค้ดสะกดชื่อฟิลด์ผิด

-src/utils/formatDate.ts (Helper Function)
 --หน้าที่: ฟังก์ชันช่วยแปลงข้อมูลเวลาในรูปแบบ TimeStamp ของระบบคอมพิวเตอร์ ให้กลายมาเป็นวันที่และเวลาที่มนุษย์อ่านเข้าใจง่ายในสไตล์ไทย (เช่น แปลงเป็น "20/05/2026")

4. ไฟล์ส่วนกลางนอกสุด (Root Configuration Files)
-.env.local (Environment Variables): ไฟล์ลับที่สุดในเครื่อง ใช้เก็บรหัสชุด Config เชื่อมต่อ Firebase ห้ามอัปโหลดขึ้น GitHub เพื่อป้องกันไม่ให้คนนอกเข้ามาเจาะหรือดึงฐานข้อมูลของทีมแข่งไปใช้งาน

-tailwind.config.ts (Style Configuration): ไฟล์สำหรับตั้งค่าชุดสีหลักของทีม (เช่น สีประจำชมรมยานยนต์) ขนาดฟอนต์ และปรับแต่ง CSS ให้รองรับหน้าจอโทรศัพท์มือถือขณะที่สมาชิกกำลังเปิดดูโค้ดอยู่หน้างานในอู่ซ่อมรถ

-package.json & package-lock.json (Dependency Management): ใบสั่งและใบเสร็จบันทึกรายชื่อ Library ทั้งหมดที่ระบบดึงมาใช้งานร่วมกัน เพื่อให้ทุกคนในทีมที่ Clone โค้ดไปจาก GitHub สามารถพิมพ์ npm install แล้วรันแอปได้ทันทีโดยไม่มีปัญหาเรื่องเวอร์ชันโค้ดไม่ตรงกัน
